# 项目状态与待验收项

当前交付范围是本机 Windows + Codex 的独立 CLI，产品验证器支持 Lean FIFO 的满时拒绝和满时覆盖两套登记规格。长期目标与本轮边界以[已审核设计](design.md#本轮发布范围与项目边界)为准。

## 已有能力

- 四类工作包、固定输入和完整交接；暂停恢复、规格变更、历史成果复用与路线失效回收。
- 共享源码三方合入，实际核验新成果及当前全部已接纳保证；失败保留封存原稿、原始 Lean 诊断和实际被检源码入口。
- 包根保留候选、规格、目标与唯一 `AGENTS.md`；连接配置在 `.codex/`，视图、按需证据/材料和临时文件在包内 `.axiward/`。核验 `.checks/` 与默认交付 `delivery/` 位于项目根并忽略。
- 从干净提交生成独立发行物，来源以 `release.json` 为准。已通过独立启动和适配器 stdio 检查；复用满时拒绝示例完成了真实 Lean 核验、默认交付和运行。

Worker 使用已批准的完全访问模式，通过说明和工具入口约束操作；不声称操作系统强制隔离。每包使用独立空间与身份，恢复不覆盖草稿或复活已删候选；未提交草稿不由 Axiward 保证保存。旧用户目录不自动迁移或清理。

## 仍需完成

- 满时覆盖规格的真实可执行交付，以及所有在途操作阻止发布的完整性质验证。
- handoff 检查在 30 秒内通过、当前源码的原生 MCP 复验和剩余覆盖审计。最近包工作区检查通过不等于全部检查通过。
- 真实模型持续推进与用户最终验收。既有 FIFO 示例的接纳和运行不能代替自主开发验证。

当前 Axiward 开发仓库尚未受 Axiward 管理。具体运行方式见[使用说明](product-guide.md)，证明对应关系与检查分类见[验证范围](execution-slice.md#验证与边界)，运行权限及外部依赖见[执行模式](permissions.md)。
