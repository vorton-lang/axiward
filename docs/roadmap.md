# 本机 CLI 发布路线

目标是 Windows + Codex 环境下、本机使用的独立 CLI 二进制。范围与长期系统目标的区别见[设计](design.md#本轮发布范围与项目边界)；当前实现和验证状态见[项目状态](status.md)。

## 当前实现

- 路线变更报告失效包；Discussion agent 停止 Codex worker 后使用控制端回收。交付完成不等待旧包回收，已登记在途操作仍须结清。
- 共享源码三方合入，按完整候选重新核验新成果及当前全部已接纳保证；原候选保持封存，冲突/失败保留现场。
- 新包直接获得不可变失败证据中的 Lean 诊断和实际被检源码入口，不额外运行核验提取报错。

具体行为见[使用说明](product-guide.md)，实际证明与检查边界见[工程说明](execution-slice.md)。

## 发行与待验收边界

`package_cli.py` 从干净提交生成独立二进制、必要运行文件和来源/摘要清单；独立目录启动与适配器 stdio 已完成预验。运行时使用已有依赖，不把整个源码仓库或完整工具链作为控制器配布形式。正式生成物的版本以 `release.json` 为准。

旧检查重整在 `34ee404` 保存为 checkpoint，不能按全部完成声明：最后的旧 handoff 检查超时，原生 MCP 最终树复验和部分覆盖审计尚未完成。新功能的独立检查结果另列于工程说明。检查通过不等于真实 agent 持续推进或用户最终验收。

## 已确定的边界

- 普通 Git 签出，`.axiward/` 入 Git，`.view/<包空间>/` 忽略；未提交草稿不由 Axiward 保证恢复。
- Worker 显式选择节点与动作，默认每包可使用全新 worker；完整交接不依赖旧上下文或已读状态。
- Worker 使用用户批准的完全访问模式和说明约定，权限隔离检查跳过。
- 本轮不要求通用安装器、广泛平台/语言接入、完整 skill/manual 配布、远端同步或自动升级。
- 当前 Axiward 源码仓库尚未被 Axiward 接管；本轮整理不隐含接管授权。
