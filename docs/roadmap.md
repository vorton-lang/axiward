# 完整路线图与当前进度

**当前已实现 R0 控制闭环；真实 agent 持续推进与用户最终验收仍待完成。** 长期目标“从模糊需求自主推进到完整规格产品”尚未全部实现。下表的工程验收指已有运行记录；最近清理后的完整回归复验尚未完成，具体边界见[项目状态](status.md)。

R0 的已确认范围是 **Windows + Codex + 一套固定验证链 + FIFO 验收项目**。下面沿用已确认的 M0–M3 编号，区分实现、工程检查和实战效果，不新增已获批准的里程碑。

## 全局位置

| 阶段 | 当前进展 | 尚未闭合的部分 |
| --- | --- | --- |
| **M0 · 验证关键接入** | Lean 4.34.0、实际产物核验、原生执行记录和用户问答通道已验证；薄适配器与原生权限已接通。 | 验证范围限当前原生入口和配置；平台与工具扩展需另行验收。 |
| **M1 · 建立状态内核** | R0 状态转换、精化图、证据绑定、Git 持久化与恢复已实现；核心不变量已有 Lean 证明。 | 证明覆盖的是已建模转换；Git、harness、编译器等仍依赖明确的外部契约。 |
| **M2 · 接通工作流程** | 四类工作包、固定视图、资料检索、用户决定、暂停恢复、规格变更与复用已接通。Worker 明确选择节点和动作，控制器检查准入。 | 真实任务中的持续推进效果尚待用户验收。 |
| **M3 · 完成首个交付** | FIFO 源码、证明、程序与交付清单已生成；错误、变更、并发和恢复的工程验收通过。 | 固定候选和模拟答复的检查，尚未替代真实 agent 持续工作及用户最终验收。 |

**下一道门槛：用真实 agent 从已确认规格开始，持续完成一次项目，并由用户验收。** 这项实战验证尚未执行，也不承诺开放任务必然收敛。当前用户要求先完成本机 CLI 的仓库布局与合入设计，暂不运行检查。

## 长期目标还有哪些部分

以下是既有设计目标与当前实现的差距，**尚未确定新里程碑编号、排期或实现方案**。

| 方向 | 已有基础 | 仍需完成 |
| --- | --- | --- |
| 模糊需求 → 用户可读、可机器核验的规格 | 已确定由 skill 负责需求澄清，用户对规格含义负责。 | 将实际规格生成工作流接入；当前入口接受已确认、已登记的根规格。 |
| 不同产品与语言的验证 | 精化图、证据版本与固定验证器契约已可用。 | 当前验证器仅覆盖 Lean FIFO 两个规格；通用 Lean 项目、Rust/Verus 等接入尚未实现。 |
| 更广的探索与外部结论 | 先准入、登记操作、收取原始结果、单独保存解释。 | 项目实验原语目前只有固定候选核验；其他实验和外部证据需分别建模。 |
| 主观品质与人类验收事实 | 独立用户问答与版本绑定已可用。 | 一般性主观验收项如何成为根规格授权的事实，尚未作为通用验证契约接入。 |
| 权限与运行环境保障 | 仓库与视图分离，原生权限、薄适配器和受限核验已接通。 | 新工具通道、其他 harness 与平台需要重新接入和验证。 |

## 已确认的实施约束

- **D5**：CLI 暂定使用 Lean；语言或工具链导致的实际问题由用户评估。
- **D6 的当前解释**：Windows 嵌套目录隔离不可用后，用户批准 worker 使用完全访问权限和说明文档，跳过权限部分；薄适配器保留工具入口与归属检查。
- **D7**：允许随 harness 启停的薄适配器；没有独立项目守护进程。
- **信任边界**：用户确认规格；证明与观测各自依赖声明的验证器和设施契约。测试通过不替代数学证明。

设计依据：[已审核系统设计、交互选择与交付要求](design.md)、[已审核状态规则](kernel-contract.md)。
