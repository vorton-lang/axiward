# 本机 CLI 发布路线

目标是 Windows + Codex 环境下、本机使用的独立 CLI 二进制。范围与长期系统目标的区别见[设计](design.md#本轮发布范围与项目边界)；当前实现和验证状态见[项目状态](status.md)。

## 两项设计未决

| 议题 | 当前实现 | 需要确定的规则 |
| --- | --- | --- |
| 项目完成时如何处理旧路线活动包 | 换路线不自动取消旧包；`complete` 只要求当前路线无活动包，但所有已登记在途操作必须结清。 | 是否要求所有活动包结束后才宣布项目完成，包括已离开当前路线的包。Agent 建议要求全部结束，尚未获批。 |
| 多包源码合入 | 状态提交使用 Git CAS；子节点产物各自保存，FIFO 按选定实现组合后核验，没有通用源码 merge。 | 明确共享源码的合入对象、基准及相关读写依赖；无冲突修改如何合并、合并后核验什么。已有“冲突结束旧包、保留候选、新 HEAD 新包继续”规则，检测入口仍依赖本项。 |

以上按两个设计议题计数；未把已批准工作重复列为待决，也不将 agent 建议当作用户决定。

## 已定案、尚需完成的工作

1. 完成检查分层：已有定理覆盖的状态断言删除重复测试；必要纯逻辑补通用定理；外部成功与失败边界保留不超过 30 秒的独立检查。该方案已批准，当前由一个 subagent 实施。
2. 两项设计定案后，落实相应完成条件、源码合入及冲突检测；保持包输入固定、终稿不可改写、历史与必要过程义务不丢失。
3. 完成本机二进制与现有必要运行文件的发布整理，以及已确定范围的接入检查和使用验收。构建产物使用已安装的本机依赖，不把整个源码仓库作为控制器配布形式。

检查通过不等于已完成真实 agent 持续推进或用户最终验收；既定 R0 要求见[设计](design.md#r0-交付要求)。

## 已确定的边界

- 普通 Git 签出，`.axiward/` 入 Git，`.view/<包空间>/` 忽略；未提交草稿不由 Axiward 保证恢复。
- Worker 显式选择节点与动作，默认每包可使用全新 worker；完整交接不依赖旧上下文或已读状态。
- Worker 使用用户批准的完全访问模式和说明约定，权限隔离检查跳过。
- 本轮不要求通用安装器、广泛平台/语言接入、完整 skill/manual 配布、远端同步或自动升级。
- 当前 Axiward 源码仓库尚未被 Axiward 接管；本轮整理不隐含接管授权。
