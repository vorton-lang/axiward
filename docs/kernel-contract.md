# 状态转换规则 · 已审核

2026-09-18。本文全部规则已由用户审核通过，作为实现依据。当前 R0 的支持范围、实际证明与外部契约见[工程说明](execution-slice.md)；本文不把每项设计目标等同于已经获得的数学证明。依据已审核的[系统设计](https://github.com/vorton-lang/axiward/discussions/1)与 [CLI 设计](https://github.com/vorton-lang/axiward/discussions/2)，将既有原则展开为完整流程。

2026-09-19 补充：用户批准 worker 使用完全访问权限和说明文档，跳过权限隔离部分。下列角色、归属及准入规则继续由 Axiward 工具入口执行；当前模式不在操作系统层阻止 worker 绕过工具、直接访问文件或调用管理 CLI。

**阅读顺序：先看状态，再看四类动作，最后看变更与异常。** 每条转换都写明触发者、条件、效果和失败处理。规则编号可直接用于讨论。

## 一、系统保存什么

| 对象 | 必须保存的内容 |
| --- | --- |
| 规格与规范 | 用户确认的根规格；操作规范、权限与验证器契约；各自的版本和内容摘要。 |
| 目标节点 | 命题、实际依赖、当前精化路线，以及支撑当前闭合的证据与产物。 |
| 工作包 | 所属节点、固定动作类别、执行者、输入快照、允许的影响、阶段。 |
| 证据 | 命题或有限事实、来源、适用版本、输入和环境、核验凭据、实际产物引用。 |
| 尝试记录 | 提案、原始执行结果、资源消耗、拒绝或失败原因；模型解释单独保存。 |
| 待决事项 | 问题、答复权限、目标与版本、允许的状态变化、原工作包及来源。 |

**S1 · 节点只有两种求解状态：未闭合、已闭合。** 已闭合必须有当前有效的依据。等待、占用、有无路线是另外的属性；不设置由模型填写的“成功”字段。

**S2 · 工作包有五个阶段。**

| 阶段 | 含义 | 可以怎样离开 |
| --- | --- | --- |
| 编写中 | 生成本类动作的候选；探索尚未准入。 | 提交、探索准入、明确失败或取消。 |
| 探索中 | 已获准按固定探索契约运行。 | 提交、明确失败或取消。 |
| 核验中 | 终稿已经封存，正在核验；不能替换终稿。 | 接纳、拒绝、核验未完成或取消。 |
| 待决定 | 问题已核验并登记，等待用户答复。 | 用户答复或显式取消。 |
| 已结束 | 保留终稿与结局，释放节点占用。 | 不重新打开；后续工作领取新包。 |

“已结束”可对应接纳、拒绝、失败、未知、超时或取消；它不表示目标已闭合。暂停只阻止继续调度，不改写工作包阶段。

**S3 · 没有占用时限。** 除“已结束”外均占用所属节点；同一节点至多一个包。暂停、用户离开和长时间无响应都不自动释放占用。

**S4 · 三种关系分开记录。** 溯源关系说明工作为何服务于根；证明依赖决定哪些变化会使结论失效；尝试关系保存走过哪些路线。不能因为都出自同一根，就把所有节点都判为失效。

**S5 · 当前状态与历史分开。** 路线被替换、结果失效、工作被取消，都只改变当前引用和有效性；已经发生的操作及其当时依据保留。

## 二、所有转换共用的规则

**G1 · 权限来自真实通道。** 模型可提案、提交和请求取消自己的包；控制端负责分派与核验；harness 提供原始执行记录；用户入口提供决定与根规格变更。JSON 中的身份、通过标记、日志文字都不能产生这些权限。

**G2 · 先证明操作可以做，再做。** 每项项目操作绑定目标、输入、适用规范和允许的影响。模型只能选择已建模操作及其参数；没有准入依据的操作不进入执行。

**G3 · 工作基于固定快照，接纳检查当前依赖。** 快照固定目标、实际读取或引用的材料及版本、当前路线、相关规范，以及待写位置的原始版本。补充材料仍来自同一快照。提交只检查有关依赖和写入冲突，仓库中无关提交不使工作过期。

**G4 · 依赖不能由模型任意删减。** 证明、构建和实际执行使用的前提必须纳入绑定。验证器与适配层负责确认绑定完整；当前依赖变化后，旧凭据须重新核验才能使用。

**G5 · 每次接纳有明确效果。** 返回结果分别说明：操作是否接纳、工作包是否结束、节点是否闭合、当前交付是否完成。不得用一个“通过”混在一起表示。

**G6 · 两种拒绝分开。**

| 拒绝对象 | 处理 |
| --- | --- |
| 无法识别归属的消息、错误身份、越权请求 | 拒绝并由接入层留存；不改变目标，也不结束别人的工作包。 |
| 已确认归属并登记的正式尝试 | 拒绝原因进入该包历史；结束本包并释放占用，回到主循环。旧成果保持，失效成果不能重新变有效。 |

**G7 · 未获证明不等于命题为假。** 证明错误、验证器失败、超时、预算耗尽或没找到解，都不能凭此产生反证。只有经核验的反例才能排除其准确指向的候选。

## 三、开始工作与访问材料

**T1 · 初始化。** 用户提供已确认的根规格和操作规范；控制端检查表示、版本与工具契约可用，创建未闭合根节点和首份 Git 快照。失败则不创建可工作的正式状态；不自行补写用户未确认的要求。

**T2 · 领取工作包。** Worker 明确指定节点与四类动作之一。控制端检查节点未闭合、未占用及该类动作的准入条件，通过后固定执行者、动作、快照与权限，登记“编写中”。准入失败不占用节点；领取后的模型不能换类。省略选择只能恢复该工作空间已经绑定的包，不能自动领取新包。

不是所有未闭合依赖都会阻止所有动作：可探索、精化或请求决定；但执行交付必须具备其证明所需的前提。执行交付须遵守当前路线；改变路线归入精化。

**T3 · 读取或补充视图。** 执行者申请读取；控制端按权限从本包快照检索或导出。补充材料更新视图记录，不修改目标、路线或正式源码。纯查询不产生目标状态转换；拒绝读取不结束工作包。

当前权限已撤回的材料不能继续导出。已经进入模型上下文的内容不会因权限变化自动消失；系统也不声称具有这种能力。

**T4 · 登记终稿。** 所属执行者提交本类动作的最终候选；控制端固定请求 ID、内容摘要、包 ID 和输入绑定，将包转为“核验中”。此后候选不可改写。缺证明、证明不成立、错类或过期等问题在核验中拒绝，按 G6 结束本包。

同一终稿的核验恢复不算再次提交；修改候选必须领取新包。待决定或已结束的包不能用新终稿覆盖已有内容。

## 四、四类动作

### 执行

**T5 · 接纳执行结果。** 控制端核验：当前目标与有关依赖仍匹配；实现、证明与实际交付物绑定；操作及其必要过程义务满足规范。全部满足后，原子接纳产物与证据、关闭对应目标、结束本包。

不满足则记录具体结局、结束本包，目标保持未闭合；不得在原包内进入修补重交循环。正式源码不会被被拒绝的候选替换。

### 精化

**T6 · 接纳分解或替换路线。** 控制端核验子目标、实际依赖、组合方式，以及“子目标和必要前提成立足以满足父目标”的证明。引用必须存在且版本正确，证明依赖和精化关系不得形成循环。

通过后原子加入新节点并选择新路线，结束本包。已有节点的命题不能被模型原地改写；改变子目标须形成新版本或新节点，并重新核验它与父目标的关系。旧路线与仍有效成果保留，新子目标不会因为精化成功而自动闭合。

精化也可把当前节点恢复为直接实现：保留原命题与必要前提，撤下当前分解路线，使目标继续保持未闭合；控制端核验没有削弱原有义务。不能通过撤掉子目标同时把原目标标成完成。

替换路线后，Axiward 提示不再被当前路线实际依赖的活动包及 owner；共享节点仍被当前路线依赖时保留。Discussion agent 立即通过 Codex 停止失效 worker，再调用控制端取消入口回收包。历史候选和成果保留，已经登记的在途义务仍须结清。

**T7 · 接纳复用。** 精化包可以引用已有产物或证明。控制端核验它们对当前目标、当前依赖和实际产物的适用性；通过后接入当前路线。若已经足以满足目标，按统一闭合规则关闭目标；否则只更新路线。复用不要求重写产物，但不免除适用性核验。

T6、T7 任一核验失败，保留原路线和成果，记录拒绝并结束本包；不得留下只安装一半的子图。

### 探索

**T8 · 探索准入。** 执行者提交探索方案；控制端核验目标关联、允许的操作、状态保持条件、资源与影响边界、结果解释规则及退出条件。通过后封存方案，转为“探索中”；不通过则记录拒绝、结束本包。

包内可以多轮调用，但每一步必须属于获准方案。超出方案的改动需结束本包，由 worker 重新选择工作并申请准入；方案允许的参数或分支选择不算改方案。

**T9 · 开始一次外部操作。** 控制端确认探索已准入、该操作仍获授权且资源条件满足，先持久化操作 ID、准确参数、输入版本与准入依据，登记需要预留的资源额度，再交给 harness 执行。登记后记为“在途”，直到得到可信结果或确认未执行。

准入记录写入失败就不发起操作。预算不足或权限不满足时不发起新调用；按契约暂停或结束。操作一旦可能已经执行，就不能用“取消”假装其副作用不存在。

**T10 · 记录执行结果。** harness 回传绑定该操作的真实结果；控制端追加原始记录，检查完整性及观测契约。模型解释另存。此步不直接关闭产品目标。

缺少终止记录、输出截断或来源无法核实时，只能保留已知范围及“未知”；不能据此生成要求完整观测的证据。包结束后到达的结果仍归档到原操作，不能重新打开原包或复活其候选。

**T11 · 接纳探索成果。** 执行者封存成果，控制端按事先获准的解释规则核验并统一入图：

| 成果 | 入图后的效力 |
| --- | --- |
| 引用、建议、候选解释 | Worker 的参考材料或待证命题。 |
| 满足观测契约的记录 | 只对已绑定输入、版本和环境成立的有限事实。 |
| 经核验的外部证明、证书或反例 | 在声明的信任条件和适用范围内支持命题或排除候选。 |

通过后结束本包。没有收获也是合法结局。探索结束本身不会关闭产品目标；若产生足够的有效证据，仍须经过统一闭合规则。核验失败则记录并结束，不发布未核验结论。

尚有在途操作时，先完成结果对账；不能把“观察不到结果”当成“操作没有影响”。其未解决过程义务即使在包结束后也继续保留。

### 请求决定

**T12 · 发出请求。** 控制端核验问题是否具体、与目标的关系、谁有权回答、涉及哪些版本和产物，以及各答复分支允许怎样改变状态。通过后先保存待决事项，再通知用户；工作包转为“待决定”。核验失败则结束本包。

等待只阻塞该节点及依赖该决定的工作。通知失败不丢弃问题，也不把它记为已回答。

**T13 · 接纳用户答复。** 独立用户入口提供答复。控制端检查来源与作用范围；仍适用时，原子保存答复、执行对应的已建模变更并结束本包，然后在当前调用和后续相关工作的完整交接中提供决定。

答复若明确确认了某份新根规格，就按 T17 更新；若确认的是“该产物满足一个由用户验收的项目”，只产生该规格已授权的验收事实。一般性的“同意”不能凭空证明软件性质。

作用范围已过期时，答复作为历史输入保留、结束本包，不应用于新版本；需要时重新请求。答复超出既定分支时，同样只记录输入并结束本包，后续再形成可核验的变更；模型不能自行把自由文本扩大为授权。

原调用没有收到回包时，已保存的决定仍参与后续交接。每次读取重新核对当前目标、版本和依赖；不以答复时的适用标记或任何 worker 的已读状态代替当前判断。新 worker 得到原目标和来源明确的决定，不因此获得更大授权。来自模型的伪造答复按 G6 拒绝，不结束真正等待用户的包。

## 五、闭合、变更与暂停

**T14 · 统一闭合。** 控制端自动检查证据能否支持当前目标：命题和版本匹配，实际依赖均有效，必要过程义务已满足，证明绑定实际产物；有组合路线时，子目标与组合证明都必须适用。全部成立才发布当前结果。

闭合与导致闭合的接纳在同一次转换中生效，或作为随后独立核验的转换生效；不得先标完成再补证明。父节点另有活动包时，自动组合暂缓，待该包结束后按最新状态核验。

组合证明失败只表示父目标仍未闭合，原因留档；不撤销仍有效的子目标成果。控制端可以继续向上组合，不能绕过证明直接传播“完成”标记。

**T15 · 明确结束或取消。** 所属执行者可以报告失败、未知、超时或请求取消；用户和控制端也可按权限取消。保存候选、事实与原因，释放占用，后续领取新包。已经核验的独立成果不因取消消失。

取消须停止继续发起操作；已经在途的操作仍要记录和对账。取消核验中的包后，迟到的核验结果只能留档，不能发布该终稿。

**T16 · 暂停与恢复。** 用户暂停、运行预算耗尽或外部条件阻断时，保存具体原因，停止新的工作分派和操作发起；现有包不自动结束。必要的结果收取、用户答复、取消和保存仍可进行。

条件恢复后从原图继续，并按最新规范检查后续操作。没有独立守护进程定时回收、调度或代替用户答复。

**T17 · 用户变更根规格或规范。** 独立用户入口确认新版本；控制端保存新根或规范、保留旧版本，撤去不再适用的当前结果和路线依据，并沿实际证明依赖传播失效。无关目标、产物与证明保留。

子目标的改写通过 T6 建立新的精化关系；不能通过变更一个子目标就绕过父目标的要求。验证器或基础设施契约改变，也按相关证据的实际依赖处理。

历史操作是否合规继续依据其执行时的授权与规范。旧包保留原输入快照；受影响的后续操作暂停放行，终稿须用当前依据重新核验。若不能建立对应关系，则拒绝本次提交；并不自动要求重写或重跑已有产物。

**T18 · 发布当前交付完成状态。** 控制端确认当前根和全部必要过程义务已闭合，证据绑定同一份实际交付快照，并且没有尚未收束、可能影响该交付的操作，才将该快照记为完成。

已放弃的历史路线无须全部闭合，但其真实操作留下的必要义务不能随路线一起丢弃。无关且不影响交付的支线不阻塞完成；交付条件满足即宣布 `complete`，不等待旧 worker 停止或旧包回收。之后根、依赖或产物变化，重新计算当前完成状态；历史交付记录保留。

## 六、持久化、冲突与恢复

**P1 · 一次正式转换，一份完整快照。** 规格、源码、图和推进记录共用一条 Git 历史。状态与本次接纳产物一起提交；不允许状态指向尚未持久化的证明或产物。此前明确准入的外部效果由 T9、T10 单独记录，Git 回退不能撤销现实副作用。

**P2 · 更新必须比较旧版本。** 提交只能把自己读取的仓库版本替换为新版本。版本已被其他任务推进时，本次写入不生效；重新读当前状态并重跑转换条件。依赖未变且写入不冲突时可继续；相关依赖或同一待写位置变化时须重新核验或拒绝，不能覆盖另一任务，也不能未经核验就合并两份产物。

已批准的内容冲突处理：前包接纳并推进 HEAD，后包一旦被合入流程判定冲突，就记录原因、结束包并保留候选；后续包以新 HEAD 为输入，交接提供旧候选与冲突信息，修改后重新核验。旧包不重绑输入、不修改封存终稿，不新增包内解冲突阶段。复用原 worker 的上下文仍须领取新包。当前合入对象是共享源码候选树，以包领取时的源码为基准，与最新正式源码三方合并；封存原稿不变。无冲突时核验实际合并树上的新成果及当前路线仍需成立的全部已接纳成果，尚未完成目标不提前要求通过。失败不改变原正式源码或已有成果。首版按完整候选依赖粒度重验，不记录细粒度读依赖；核验后的提交竞争要求重新合并和核验。

**P3 · 同一请求只生效一次。** 请求 ID 绑定身份、包、命令和内容摘要。完全相同的重试返回已有进度或结果；相同 ID 携带不同内容直接拒绝。并发重试也不能多次释放占用、发布成果或记录用户决定。

**P4 · 崩溃不推断成功或失败。** 重启加载最后一份完整快照：编写中和待决定继续保留；核验中恢复同一终稿；已结束不会复活。快照结构或不变量不满足时停止正式转换并报告，不能把损坏状态当成空项目重新初始化。

当前不维护已读状态。历史 `acknowledge` 请求及其结果仅为既有日志解码、原样回放保留；新工作没有对应入口，不改写旧历史，也不由旧确认记录省略交接内容。

**P5 · 外部操作不盲目重放。** T9 已登记而 T10 尚无可信结果时，先向 harness 查询和对账。只有确认未执行，或契约保证相同操作 ID 的重试不会重复产生效果，才允许重新发起；否则保留未知与相应过程义务。

**P6 · 持久化失败不算转换成功。** 未写入正式历史的提案不得对外宣布接纳、完成或已记录决定。成功写入但回包丢失时，客户端按 P3 重试。用户通知失败只影响通知，不撤销已落盘的决定。

## 七、实现必须证明什么

以下是对上述转换的证明目标，不是已经获得的保证。

1. **权限与阶段**：越权、错阶段和错动作的输入不能改变正式成果；也不能释放别人的占用。
2. **占用与终稿**：一个节点至多一个活动包；终稿登记后不可替换；结束后不能复活；时间流逝不结束包。
3. **证据与闭合**：没有当前适用的核验依据就不能闭合；依赖改变不能继续沿用失效结论；模型解释不能冒充证明或原始事实。
4. **精化与溯源**：新路线有通向根的依据；依赖无循环；子目标成立加上当前组合证明才能支持父目标。
5. **历史与复用**：转换保留历史；变更只影响相关有效性；失败候选不覆盖正式成果；取消不抹去真实副作用。
6. **存储与并发**：正式变更不可部分生效；并发不能覆盖；相同请求不重复生效；完成状态与实际交付快照一致。

Lean 内核证明其实际状态转换满足这些规则。Git、harness、验证器及编译产物的外部对应关系，分别依照明确的契约接入和验证；非空证书编号不等于证明通过。

本文覆盖完整流程语义。R0 实现内核、Git 持久化、真实视图、四类工作流程与用户入口，验证器和操作原语采用已登记的有限契约。当前按用户已批准并再次明确的要求，使用原生权限限制 worker，由 harness 托管的薄适配器访问正式仓库；不再用文本规则代替权限实现。
