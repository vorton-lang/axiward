# Axiward M0 原型验证汇总

2026-09-18 · **已有足够证据进入 M1 状态内核实现。** 强制隔离依用户决定后补，不把它标为已完成。

## 已确认的实施前提

- CLI 暂定 Lean；遇到由语言或工具链造成的实际阻碍，及时交由用户评估。
- 初版可用完全访问权限＋访问规则文本，权限系统问题不阻塞 probe。
- 允许由 harness 托管薄适配进程；适配器不管理独立后台任务或项目状态。

## 下一工作包：M1.1 / M1.2

将已有系统规范写成状态转换契约，并实现、证明最小状态内核：

1. 一个节点只能有一个活动工作包；占用不自动过期。
2. 执行者只能沿被分派的四类流程提交。
3. 未满足证明、版本或授权要求的提交不能推进正式成果状态；尝试记录保留。
4. 用户决定与机器观测使用独立来源和明确作用范围。
5. 根或依赖改变后，受影响结果需要复核，历史操作记录保留。
6. 必要义务未闭合时，不能声明根目标完成。

先完成纯状态转换与不变量证明，再在 M1.3 接 Git 持久化；不把 Git、harness、验证器的外部行为假装成已经由内核证明。
