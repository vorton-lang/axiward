通过 Codex `command/exec` 的原始输出流采集，不经模型转述。控制端把调用绑定到当前 harness 提供的任务 ID、工作包、输入快照摘要和进程 ID。

| 对照 | 结果 |
| --- | --- |
| 完整采集 | 收到 stdout 200,062 字节、stderr 70,000 字节；内容与预期一致 |
| 程序输出自称 PASS、退出码 0 | harness 的真实退出码仍记录为 7 |
| 模型自造一份“harness 日志”JSON | 无已登记的原生记录引用，不能当作机器事实接纳 |
| 引用不匹配的任务或输入版本 | 拒绝用于该上下文 |
| 原生输出上限造成截断 | 识别 `capReached`，不能作为完整记录接纳 |
| 缺少结束事件 | 保持不完整 |
| 已存输出被改写 | 长度 / 摘要核对失败 |

**失败运行可以形成有效观测；有效观测不等于产品满足规格。** 本例接纳的是“该过程实际退出 7”的事实。
